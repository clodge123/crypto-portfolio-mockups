🆡 HOW FLEX WATERFALL WORKS
• Every block type has a width class: full (100%), half (50%), or third (33%)
• Blocks flow left-to-right, wrapping to next row when width runs out
• Row height is determined by the tallest block in that row
• Card height is fixed (580px). If blocks exceed it — scale down proportionally or overflow to detail
• If blocks under-fill — scale up proportionally to fill the card

Always takes the whole row. Best for data that needs horizontal space.

◊ SCALING: How Blocks Fit the Fixed Card

Card available height: ~520px (580 - 60 for header)
Block natural total: Sum of all block heights at their "ideal" size
Scenario Scale Factor Result
natural total < 520px ×1.0 to ×1.5 Blocks scale UP to fill card. Generous spacing.
natural total ≈ 520px ×1.0 Perfect fit. Blocks render at natural size.
natural total 520-780px ×0.66 to ×1.0 Blocks scale DOWN. Still readable, compact but comfortable.
natural total 780-1040px ×0.5 to ×0.66 Dense mode. Mini blocks, 3-col splits. Some T2 blocks → detail.
natural total > 1040px ×0.5 min Overflow mode. All T2+T3 → detail. Card shows headlines only.

◊ OPTION COMPARISON MATRIX

Option How Blocks Fit Pros Cons
A: 2-Col Grid All blocks same height, 1-col or 2-col width Most predictable. Dead simple math. Forces some blocks into half-width awkwardly.
B: Priority Tier T1 blocks big, T2+ shrink/overflow Best data prioritization. Detail page is natural. Need LLM to tag priorities. Less predictable layout.
C: Equal Units Card ÷ N = equal rows for all Perfect consistency. Cleanest code. One-size-fits-all. Charts cramped with many blocks.
D: Flex Waterfall Width-class based. Blocks flow & wrap naturally. Most natural. Blocks sizes match their content. No forced sizing. Most complex layout engine. Row heights can vary.

◊ MY TAKE: HYBRID RECOMMENDATION

I think the best approach combines elements from multiple options:
✦ Use Option D (Flex Waterfall) as the base rendering engine — blocks have natural width classes and flow naturally
✦ Borrow Option B's priority tiers for the card vs detail split (T1 always on card, T2 flexible, T3 detail)
✦ Scale proportionally like Option A — total block height vs card height = scale factor
This gives us: Natural block sizes + Intelligent overflow + Always-filled card + No awkward forced sizes
